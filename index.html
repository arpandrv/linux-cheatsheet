Filtering & patterns

17 examples

Search text, extract fields, and summarize files.

CommandWhat it does
grep -n 'error' server.log

Find matching lines and show line numbers.

grep -i 'error' server.log

Match text without regard to letter case.

grep -v '^#' config.conf

Filter out lines starting with #; indented comments and blank lines remain.

grep -F 'a.b' file.txt

Find literal a.b; the dot is not treated as a regex wildcard.

grep -E 'error|warning' server.log

Match either expression with extended regular expressions.

grep '^ERROR' server.log

Match ERROR only at the beginning of a line.

grep 'done$' file.txt

Match done only at the end of a line.

grep -E '[0-9]+' file.txt

Find lines containing one or more ASCII digits.

grep -rn 'TODO' ./src

Search files recursively below src and show matching line numbers.

wc -l file.txt

Count newline characters; normally the line count for a text file.

sort names.txt

Sort lines using the current locale's ordering.

sort -n numbers.txt

Sort lines by their leading numeric value.

sort names.txt | uniq -c

Group identical lines and count occurrences; uniq alone only combines adjacent duplicates.

cut -d ':' -f 1 /etc/passwd

Extract the first colon-separated field: account names.

tr '[:lower:]' '[:upper:]' < file.txt

Convert lowercase text from standard input to uppercase.

sed 's/old/new/g' file.txt

Print text with every old match replaced by new on each line. The input file is unchanged.

awk '{print $1}' file.txt

Print the first whitespace-separated field from each line.

Globs and regular expressions are different. The shell expands filename globs such as *.txt and file?.txt. Grep searches file contents: ^ anchors the start, $ the end, and . matches one character. With grep -E, + repeats and | means either expression. Quote patterns; use -F for literal text. Grep reference.

Pipes & redirection

9 examples

Send input, output, and errors where you need them.

CommandWhat it does
printf '%s\n' 'APP_ENV=development' > app.conf

CAUTIONCreate app.conf with one setting, replacing existing contents.

printf '%s\n' 'PORT=8080' >> app.conf

Append a setting to app.conf, creating the file if needed.

sort < names.txt

Feed a file into a command's standard input.

ls /etc /missing > output.txt 2> errors.txt

Send normal output and errors to separate files, replacing their contents.

ls /etc /missing > combined.log 2>&1

Send both output streams to one file. The order of redirections matters.

ls /etc > /dev/null

Discard normal output; errors still appear in the terminal.

ls /etc | tee listing.txt

Display output and write it to a file, replacing that file's contents.

ls /etc | tee -a listing.txt

Display output and append it to a file.

printf '%s\n' '# local note' | sudo tee -a /etc/hosts

Append a comment to a protected file. tee runs with privileges; the shell's > operator would not.

Redirections are processed left to right. > file 2>&1 first points standard output at the file, then points errors at the same destination. | passes standard output to the next command; it does not include errors by default. Never redirect a command into the same file it is reading: the shell can truncate it before reading starts. Bash reference.

Permissions & ownership

22 examples

Control who can read, write, and execute.

CommandWhat it does
ls -l script.sh

Inspect a script's permissions and ownership.

chmod +x script.sh

Add execute permission, subject to the current umask.

chmod u+x script.sh

Add execute permission for the owner only.

chmod g+w file.txt

Add write permission for the file's group.

chmod o-r file.txt

Remove read permission for others.

chmod g=rx file.txt

Set group permissions to read and execute exactly.

chmod 755 file

Set owner rwx, group r-x, and others r-x.

chmod 755 script.sh

Make a script writable by its owner and executable/readable by everyone.

chmod 644 file.txt

Set owner read/write; group and others read only.

chmod 700 private.txt

Give the owner read/write/execute; deny all access to group and others.

chmod 777 file

CAUTIONGives everyone read, write, and execute access. Not a general fix for permission errors.

sudo chown alice app.py

Change the file's owner to Alice.

sudo chown alice:developers app.py

Set owner to Alice and group to developers.

sudo chgrp developers app.py

Change only the group.

sudo chown lovish:developers project

Change ownership of the project directory itself.

sudo chown -R lovish:developers project

CAUTIONChange ownership recursively. Verify the target path before running.

sudo touch /opt/project.txt

Create the shared example file if it does not exist.

sudo chown alice:developers /opt/project.txt

Assign Alice and developers to the shared example file.

ls -l /opt/project.txt

Inspect the shared example file.

sudo chmod 640 /opt/project.txt

Owner can read/write; group can read; others have no access.

chmod 600 private.txt

Allow only the owner to read and write; no execute permission.

umask -S

Show the current shell's creation-permission mask in symbolic form.

Read permissions as owner / group / others.
r = 4 Read
w = 2 Write
x = 1 Execute / traverse
755 rwx r-x r-x
644 rw- r-- r--
640 rw- r-- ---

For directories, read lists names, write changes entries (usually requiring traverse permission too), and execute lets you enter. The first character indicates type: - file, d directory, l symbolic link.

Crontab entries are configuration, not terminal commands.
1st field Minute: 0-59
2nd field Hour: 0-23
3rd field Day of month: 1-31
4th field Month: 1-12
5th field Weekday: 0-7
0 or 7 Sunday

nmcli --ask device wifi connect 'My Wi-Fi'

Connect to the named Wi-Fi network and prompt for credentials instead of putting the password in shell history.

sudo ip link set dev enp1s0 up

Bring an interface up; this alone does not assign an IP address.

sudo nmcli connection modify 'Wired connection 1' ipv4.method manual ipv4.addresses 192.168.1.50/24 ipv4.gateway 192.168.1.1

Save a static IPv4 address and gateway in this profile. Substitute an unused address and your actual network settings.

sudo nmcli connection modify 'Wired connection 1' ipv4.dns '1.1.1.1 9.9.9.9' ipv4.ignore-auto-dns yes

Set explicit DNS servers in the profile, ignoring automatically supplied IPv4 DNS.

sudo nmcli connection modify 'Wired connection 1' ipv4.method auto ipv4.addresses '' ipv4.gateway '' ipv4.dns '' ipv4.ignore-auto-dns no

Switch the profile back to DHCP and automatic DNS, clearing the manual IPv4 settings above.

sudo nmcli connection up 'Wired connection 1'

CAUTIONActivate the profile to apply saved settings. Changing a remote connection may disconnect SSH; use console access or a recovery plan.

Use the tools that manage your system. ip and ss inspect kernel networking; nmcli requires NetworkManager; resolvectl requires systemd-resolved. Other systems may use Netplan or systemd-networkd. Replace interface names, profile names, addresses, gateways, and DNS servers with your own. Static and DHCP profile examples are alternatives; activate the profile after saving the desired settings. SFTP, not FTP. FileZilla should use SFTP on port 22 with the same SSH credentials. Inside SFTP, ls lists remote files and cd changes the remote directory. rsync site/ copies the contents; rsync site may create an extra site directory. Permissions at the destination still apply.
